# findByName( name )

Retrieves a node from the faker tree by its name or path. Use it to replace the
logic of an existing node or to add your own nodes, so that [fake](./fake.md) and
the mocked API responses produce data that makes sense in your business domain.

| Parameter | Type   | Description                                |
|-----------|--------|--------------------------------------------|
| name      | string | The name or path of the node to retrieve.  |

A node can be referenced in three ways:

| Reference     | Example          | Description                                        |
|---------------|------------------|----------------------------------------------------|
| Name          | `'name'`         | The simple name of the node.                       |
| Absolute path | `'/person/name'` | The location of the node, starting from the root.  |
| Relative path | `'middle/name'`  | A path relative to any matching node in the tree.  |

## Returns

| Type           | Description                               |
|----------------|-------------------------------------------|
| [Node](#node)  | The matching node from the faker tree.    |

## ROOT_NAME

The constant `ROOT_NAME` holds the name of the root node (`"root"`). Use it to add
new top-level nodes:

```javascript
const root = findByName(ROOT_NAME)
```

## Node

| Property   | Type                              | Description                                                                                        |
|------------|-----------------------------------|----------------------------------------------------------------------------------------------------|
| name       | string                            | The unique name of the node.                                                                       |
| attributes | string[]                          | Names matched against the request path or schema properties (e.g. `frequency`).                    |
| weight     | number                            | How strongly this node indicates its parent's domain. See Domain [detection](#Domain%20detection). |
| children   | Array&lt;Node&gt;                 | The child nodes. Push or unshift objects here to add new nodes.                                    |
| fake       | (r: [Request](#request)) => any   | Generates the value. Assign a new function to override the default behavior.                       |

When adding a node, only `name` and `fake` are required. `attributes`, `weight`
and `children` are optional.

## Request

The object passed to a node's `fake` function.

| Property | Type                  | Description                                                                        |
|----------|-----------------------|------------------------------------------------------------------------------------|
| path     | string[]              | The path to the value, e.g. from the API endpoint or a nested object structure.    |
| schema   | JSONSchema            | The schema of the value to generate.                                               |
| context  | [Context](#context)   | Values generated by other nodes, for data that depends on each other.              |

## Context

| Property | Type                     | Description                                      |
|----------|--------------------------|--------------------------------------------------|
| values   | { [name: string]: any }  | A map of names to previously generated values.   |

Use the context to keep related values consistent. For example, an email address can
be built from a previously generated first and last name, or street, zip and city can
all come from the same address.

## Domain detection

Many property names are ambiguous. A `name` can be a person's name, a product name or a category name. To resolve this,
Mokapi looks at all properties of an object and decides which domain the object belongs to.

The direct children of the root node are the domains (for example `product` or `category`). The children of a domain
describe the properties that are typical for it, and their `weight` expresses how strongly a property points to that
domain.

For an object schema, Mokapi calculates a score for each domain:

1. Take all property names of the schema.
2. For each domain, add up the weights of its children that list one of the property names in their `attributes`. The comparison is case-insensitive.
3. The domain with the highest score wins. If no domain scores above 0, no domain is used.

The name of the winning domain is appended to the request path. Nodes below the domain, such as `product/name`, can then
match the object's properties. If the last element of the path is already a known domain, nothing is appended.

Only `attributes` are compared, not the node's name. A child that should count for its domain must therefore list the
matching property names in `attributes`, even if one of them is the same as its name.

For example, suppose `product` has children with the attributes `name` (weight 1), `price` (weight 2) and `sku` (weight 3),
while `category` has children with the attributes `name` (weight 1) and `parent` (weight 2):

| Properties in the schema | Score `product` | Score `category` | Detected domain          |
|--------------------------|-----------------|------------------|--------------------------|
| `name`, `price`, `sku`   | 6               | 1                | `product`                |
| `name`, `parent`         | 1               | 3                | `category`               |
| `name`                   | 1               | 1                | first domain in the tree |

When two domains have the same score, the one that comes first in the root's `children` wins. Adding a node with
`unshift` therefore gives it priority in a tie.

`weight` has no effect outside of domain detection. It only matters for nodes that are children of a domain.

## Examples

### Add a new node

```javascript
import { fake, findByName, ROOT_NAME } from 'mokapi/faker'

export default function() {
    const frequencies = ['never', 'daily', 'weekly', 'monthly', 'yearly']

    const root = findByName(ROOT_NAME)
    root.children.unshift({
        name: 'Frequency',
        attributes: ['frequency'],
        fake: () => frequencies[Math.floor(Math.random() * frequencies.length)]
    })

    console.log(fake({
        type: 'object',
        properties: {
            frequency: { type: 'string' }
        }
    }))
    // e.g. { frequency: 'weekly' }
}
```

### Generate addresses for your own country

This example overrides the existing name and address nodes. Street, house number,
zip and city are taken from the same address by storing it in the context, so the
generated address is always consistent.

```javascript
import { findByName } from 'mokapi/faker'

const firstnames = ['Anna', 'Luca', 'Mia', 'Noah']
const lastnames = ['Müller', 'Meier', 'Schmid', 'Keller']
const addresses = [
    { street: 'Bahnhofstrasse', houseNumber: '12', zip: 8001, city: 'Zürich' },
    { street: 'Marktgasse', houseNumber: '5', zip: 3011, city: 'Bern' },
    { street: 'Rue du Rhône', houseNumber: '48', zip: 1204, city: 'Genève' }
]

const random = (list) => list[Math.floor(Math.random() * list.length)]

export default function() {
    findByName('firstname').fake = () => random(firstnames)
    findByName('lastname').fake = () => random(lastnames)

    // Pick one address per context and reuse it for all address parts
    const getAddress = (ctx) => {
        let address = ctx.values['selected_address']
        if (!address) {
            address = random(addresses)
            ctx.values['selected_address'] = address
        }
        return address
    }

    findByName('street').fake = (r) => getAddress(r.context).street
    findByName('house/number').fake = (r) => getAddress(r.context).houseNumber
    findByName('city').fake = (r) => getAddress(r.context).city

    // Respect the schema type: zip can be a string or a number
    findByName('zip').fake = (r) => {
        const zip = getAddress(r.context).zip
        return r.schema.type === 'string' ? zip.toString() : zip
    }
}
```

With these nodes in place, every mocked response and every call to `fake` that
contains an address returns one of your addresses.
